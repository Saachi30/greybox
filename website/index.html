How it works

You don't need to know which security tool to use for every check. Greybox connects your request to the appropriate tools and shows you what it intends to run before doing anything.

01

Declare your target

Start by defining the website or system you're authorized to test. Greybox keeps subsequent testing inside that declared scope.

02

Ask what you want to check

Instead of remembering commands, describe the check in plain English — for example, "check the open ports" or "find the technologies this website is using."

03

Review before execution

Greybox shows the proposed security command before running it. Nothing executes without an explicit confirmation.

04

Run locally and collect the results

The actual scanning tools run through the local Greybox environment. Results are stored locally and can be turned into a report.

Optional local AI with Ollama

Greybox can work without an LLM. If you want better natural-language understanding and richer report writing, you can add Ollama and run the models locally on your own machine.

Without Ollama

Greybox still works.

You can declare a target, run supported checks, perform the standard recon sweep, and generate reports without installing an AI model.

With Ollama

More natural interaction.

Ollama adds local language-model inference for requests that need more flexible intent understanding and for AI-written report summaries and vulnerability explanations.

# Install Ollama, then: ollama serve # Smaller model — intent parsing ollama pull llama3.2:3b # Larger model — report writing ollama pull llama3.1:8b

Install

Start with the Greybox CLI. The full scanning engine is set up separately because the security tools run inside a Dockerized Kali environment.

pipx install greybox-cli
Then make sure Docker Desktop is installed and running, and run:
greybox setup
Ollama is optional. Install it separately if you want local AI assistance.
py -m pip install greybox-cli
Install Docker Desktop with WSL2 enabled, launch Docker Desktop, then run:
greybox setup
Windows users need WSL2 + Docker Desktop for the full Kali scanning engine. The CLI itself does not require Docker.
pipx install greybox-cli
Install Docker, make sure the Docker daemon is running, then:
greybox setup

After setup:

greybox scope example.com greybox ask "check open ports" greybox scan example.com greybox sessions greybox report generate <session-id>

Designed to stay local

Greybox is built around the idea that security testing data should remain under the tester's control.

  • ✓ Scan traffic stays local. Security tools run on your own machine.
  • ✓ No cloud LLM required. Ollama can run the language models locally.
  • ✓ Explicit confirmation. Proposed commands are shown before execution.
  • ✓ Local session storage. Findings and sessions are stored locally.
  • ✓ Scope enforcement. Requests outside the declared target are refused.
  • ✓ No default telemetry. Optional analytics are disabled unless explicitly enabled.
