How it works

One command for a full first-pass assessment, or granular control one tool at a time - your call. Nothing runs without your yes either way.

Run the full sweep, or ask for one thing at a time

greybox scan example.com runs a complete non-destructive recon sweep - subdomains, live hosts, tech fingerprinting, ports, web vulnerabilities - end to end. Or use greybox ask "check open ports" for one tool at a time, if that's what you want instead. Every proposed command is shown and confirmed before it runs, either way.

Findings are tagged by severity, not just dumped as raw output

The local model reads what each tool actually found and organizes it: a plain-language methodology section, a severity-tagged list of real findings (critical/high/medium/low/info), and a concrete fix for each one - not a wall of unlabeled scanner text.

Get a report

Generated automatically at the end of greybox scan, or on demand with greybox report generate <session> - a PDF with the executive summary, the severity-tagged findings and fixes, and every raw result underneath, written by a local model by default.

Install

The CLI installs with no Docker required and works immediately - dry-run intent parsing, plus the two tools that need no scanning engine at all (email discovery, certificate-transparency lookups). The full Kali/local-LLM engine is a separate step you run when you're ready.

curl -fsSL https://<host>/install.sh -o install.sh bash install.sh
view script before running it
Installs the CLI first (no Docker needed for that step), then asks separately whether to set up the full scanning engine.
brew tap Saachi30/greybox brew install greybox

The full scanning engine needs WSL2, which can require a reboot to enable - the script tells you this before doing anything, never as a surprise. Installing just the CLI doesn't need WSL2 at all.

Just evaluating? pipx install greybox-cli gets you the CLI alone, zero Docker footprint, works in dry-run/intent-parsing mode immediately.

Requirements

Actual numbers, not vague tiers - so you know before you start a multi-GB download whether this fits your machine.

Tier RAM Disk GPU Notes
CLI only 2GB free ~200MB none pipx install, dry-run / intent-parsing only, no Docker
Minimum (full engine, CPU-only) 8GB total system RAM ~14GB free none Kali image (~3-4GB, includes Metasploit) + llama3.2:3b (~2GB) for CLI intent parsing - usable, not fast
Recommended (local report writing) 16GB total system RAM ~20GB free 8GB+ VRAM helps, not required on Apple Silicon adds llama3.1:8b (~4.7GB) for report writing at acceptable speed
Below minimum - - - use hosted inference for report writing only; intent parsing still needs the ~2GB tier locally

What's local, what's optional

Concrete, not reassuring-in-the-abstract - this is the part worth actually reading before you run anything.

  • ✓Scan execution is never remote. The Kali container and the tools it runs (nmap, sqlmap, etc.) always run on your own machine, against targets you declared. Your target's logs show your IP, not a third party's.
  • ✓Hosted inference, if you enable it, only ever sees parsed findings - never raw scan traffic, and it never runs a scan itself. It's off by default; turning it on is a deliberate step, not a default you have to opt out of.
  • ✓No account required. Nothing here is gated behind a login.
  • ✓No telemetry by default. If you or a self-hosted instance turns on the optional install counter, it records a random instance ID and a ping count - nothing else, and it's documented in core/telemetry.py.
  • ✓Source is public. Every install script linked above has a "view script" link right next to the copy button - not buried in a footer.
  • ✓Permissions are named up front. Docker access for the CLI/backend; macOS Automation permission for the menu bar app, requested only when you click "scan this site," never before.
